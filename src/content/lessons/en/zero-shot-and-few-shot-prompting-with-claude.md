text-foreground" data-lesson-section=""><span class="mr-2 tabular-nums font-normal text-muted-foreground">1<!-- -->.</span>Zero-shot, one-shot and few-shot prompting</h2><p class="mt-4 leading-relaxed text-foreground">A zero-shot prompt is made of instructions alone, and for many tasks that is all you need. Claude follows clear, explicit direction well. A zero-shot prompt succeeds when it states the output format and constraints, and when it explains the reason behind each rule. A rule like "never use ellipses" works better with its reason attached: the text will be read aloud by a text-to-speech engine that cannot pronounce them. Given the reason, Claude can also handle cases the rule never mentioned, because it is able to generalise from the explanation.</p><p class="mt-4 leading-relaxed text-foreground">Some requirements are easier to show than to describe, and that is when examples start to pay off. Typical cases are a summary style, a tone of voice, or a labelling convention with fine distinctions. Another is a set of instructions that keeps producing outputs that differ slightly from run to run. Putting example inputs with their outputs in the prompt is called one-shot prompting when there is one example and few-shot (or multishot) prompting when there are several. A few well-crafted examples improve both accuracy and consistency.</p><figure class="my-6"><figcaption class="mb-1.5 text-xs text-muted-foreground">When each level of prompting is the right choice</figcaption><div class="overflow-x-auto rounded-lg border border-border"><table class="min-w-full border-collapse text-sm"><thead><tr class="bg-muted/60"><th scope="col" class="px-3 py-2 text-left align-bottom font-semibold text-foreground">Approach</th><th scope="col" class="px-3 py-2 text-left align-bottom font-semibold text-foreground">What the prompt contains</th><th scope="col" class="px-3 py-2 text-left align-bottom font-semibold text-foreground">Use it when</th></tr></thead><tbody><tr class="border-t border-border align-top"><td class="px-3 py-2 text-foreground">Zero-shot</td><td class="px-3 py-2 text-foreground">Explicit instructions, format, constraints and the reasons for them</td><td class="px-3 py-2 text-foreground">The output can be fully described in words</td></tr><tr class="border-t border-border align-top"><td class="px-3 py-2 text-foreground">One-shot</td><td class="px-3 py-2 text-foreground">Instructions plus one example of the desired output</td><td class="px-3 py-2 text-foreground">The format, tone or style is easier to show than describe</td></tr><tr class="border-t border-border align-top"><td class="px-3 py-2 text-foreground">Few-shot</td><td class="px-3 py-2 text-foreground">Instructions plus several varied examples<!-- --></td><td class="px-3 py-2 text-foreground">One example still leaves outputs inconsistent, or the task has subtle patterns and edge cases</td></tr></tbody></table></div></figure><p class="mt-4 leading-relaxed text-foreground">Escalate one step at a time. Start with one example, and add more only if the output still doesn't match. Each example adds length, and as the next section explains, every detail in an example becomes something Claude may copy. Examples also extend beyond text. In one vision walkthrough, Claude misread a speedometer in km/h until example images were added to the prompt. Few-shot prompting with images doesn't always work, though, so test it on your own case.</p><p class="mt-4 leading-relaxed text-foreground">Few-shot examples are the standard fix when outputs drift in format or label spelling across similar inputs, such as a triage prompt that returns "High" on one ticket and "high priority" on the next. Asking Claude to explain its reasoning in prose does not fix this, because the problem is the output's shape, not its reasoning. Adding one untagged example after the instructions is the weakest version of the fix. A single example shows no variety, and without tags Claude cannot reliably tell the demonstration apart from the instructions. Several varied ticket-and-output pairs, each wrapped in example tags, teach the exact labels and layout you expect.</p><aside aria-label="Exam trap" class="my-6"><p class="flex items-center gap-1.5 text-xs font-semibold uppercase tracking-wide text-amber-700 dark:text-amber-400"><svg xmlns="http://www.w3.org/2000/svg" width="24" height="24" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" class="lucide lucide-triangle-alert h-3.5 w-3.5 shrink-0" aria-hidden="true"><path d="m21.73 18-8-14a2 2 0 0 0-3.48 0l-8 14A2 2 0 0 0 4 21h16a2 2 0 0 0 1.73-3"></path><path d="M12 9v4"></path><path d="M12 17h.01"></path></svg>Exam trap</p><ol class="mt-3 space-y-3"><li id="exam-trap-4" class="scroll-mt-20"><details class="group rounded-lg border border-border bg-muted/20 p-4 open:bg-muted/40"><summary class="cursor-pointer list-none"><span class="flex items-start gap-2"><span class="min-w-0 text-sm font-medium leading-relaxed text-foreground [overflow-wrap:anywhere]">Inconsistent label spelling and formatting is a reasoning problem, so asking Claude to explain its choice in prose will fix it.</span></span><span class="mt-1.5 block text-xs text-primary group-open:hidden ">Why is that wrong?</span></summary><p data-explanation="exam-trap-4" class="mt-2 text-sm leading-relaxed text-foreground">Output consistency needs examples of the required labels and layout. from</h2><p class="mt-4 leading-relaxed text-foreground">Claude learns everything an example shows, including what you did not mean to teach. Modern Claude models pay very close attention to details in examples. A shared length, sentence structure or sentiment across your examples will be read as part of the pattern. Example sets should meet three requirements:</p><ul class="mt-4 leading-relaxed text-foreground list-disc space-y-1 pl-6"><li class="pl-1">Relevant: they mirror your real use case closely, with the same kind of input and the same output shape.</li><li class="pl-1">Diverse: they cover edge cases and vary enough that Claude does not pick up unintended patterns.</li><li class="pl-1">Structured: each one is wrapped in example tags, and the set in examples tags, so Claude can tell demonstrations apart from instructions.</li></ul><aside class="my-6 rounded-lg border-l-4 border-l-amber-500/70 border-y border-r border-border bg-amber-500/5 p-4 dark:border-l-amber-400/60 practice-question predict-first" data-practice-id="predict-1"><p class="flex items-center gap-1.5 text-xs font-semibold uppercase tracking-wide text-amber-700 dark:text-amber-400"><svg xmlns="http://www.w3.org/2000/svg" width="24" height="24" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" class="lucide lucide-lightbulb h-3.5 w-3.5 shrink-0" aria-hidden="true"><path d="M15 14c.2-1 .7-1.7 1.5-2.5 1-.9 1.5-2.2 1.5-3.5A6 6 0 0 0 6 8c0 1 .2 2.2 1.5 3.5.7.7 1.3 1.5 1.5 2.5"></path><path d="M9 18h6"></path><path d="M10 22h4"></path></svg>Predict first</p><p class="mt-1.5 text-sm leading-relaxed text-foreground">A sentiment classifier's five examples are all short, positive product reviews with the same sentence structure.
