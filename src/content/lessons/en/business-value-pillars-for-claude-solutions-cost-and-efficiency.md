pillars as the skeleton of a business case</h2><p class="mt-4 leading-relaxed text-foreground">A sponsor funds outcomes, not architecture. Before a Claude solution gets approved, someone has to say what it will change for the business and how that change will be measured. The five value pillars give that argument a fixed structure. <strong class="font-semibold">Cost</strong> asks what each finished outcome costs. <strong class="font-semibold">Efficiency</strong> asks how much resource each unit of work uses. <strong class="font-semibold">Performance SLAs</strong> set the latency and availability the system has to hold. <strong class="font-semibold">Productivity</strong> counts finished, usable work per run or per person-hour. <strong class="font-semibold">Transformation</strong> names work that was not feasible before.</p><p class="mt-4 leading-relaxed text-foreground">Each pillar has to end in a number the sponsor already tracks. The evaluation guidance describes good success criteria as specific, measurable, achievable and relevant, and notes that most real applications are judged on several criteria at once. A summarisation feature might commit to a cost per finished summary, a p95 response time, a weekly count of summaries analysts accept without rework, and a new report type that nobody produced before.
