Often that identity is a single service credential that all users share. Two gaps follow from that choice. tabular-nums font-normal text-muted-foreground">2<!-- -->.</span>Keeping credentials outside the agent's boundary</h2><p class="mt-4 leading-relaxed text-foreground">An agent that reads untrusted content can be prompt-injected. If it holds a secret, an injected instruction can try to send that secret somewhere. The robust fix is to make sure the agent never has the secret. Vault environment-variable credentials work this way. The sandbox holds only an opaque placeholder, which is swapped for the real value at egress, so <strong class="font-semibold">the agent never sees the secret value</strong>. Setting <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">injection_location</code> to header-only narrows this further. Request bodies are often built from content the agent is working with, so the body is the larger exposure surface.</p><p class="mt-4 leading-relaxed text-foreground">Substitution only applies to requests going out. If a client uses the stored secret to fetch a session token, for example through an OAuth client-credentials grant, the returned token arrives in the sandbox unredacted. For exchange-based flows, perform the exchange yourself and store the resulting token in the vault.</p><p class="mt-4 leading-relaxed text-foreground">Self-hosted Agent SDK deployments get the same property from a proxy outside the agent's container. Run the container with <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">--network none</code>, which removes every network interface, and mount a Unix socket connected to a proxy on the host. The proxy injects credentials, enforces an endpoint allowlist and logs every request. The agent sees only the tool interface. A prompt-injected request to an attacker's domain then has no network path except through a proxy that refuses it.</p><p class="mt-4 leading-relaxed text-foreground">Two details decide whether the proxy actually works. First, injecting a credential into HTTPS traffic means the proxy has to read the request, so it must terminate TLS, for example with mitmproxy. The proxy's CA certificate then goes into the agent's trust store. A plain forward proxy only relays the encrypted tunnel and can neither inspect nor inject. Second, setting <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">HTTP_PROXY</code>/<code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">HTTPS_PROXY</code> on its own is not a boundary, because not every tool reads those variables: plain ssh and most database drivers ignore them. Removing the network interface enforces the boundary whatever the tool does. Give the agent's service account minimal IAM permissions, not broad ones, and route sensitive access through the proxy where possible.</p><aside class="my-6 rounded-lg border-l-4 border-l-primary border-y border-r border-border bg-primary/5 p-4"><p class="mb-1.5 flex items-center gap-1.5 text-xs font-semibold uppercase tracking-wide text-primary"><svg xmlns="http://www.w3.org/2000/svg" width="24" height="24" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" class="lucide lucide-target h-3.5 w-3.5 shrink-0" aria-hidden="true"><circle cx="12" cy="12" r="10"></circle><circle cx="12" cy="12" r="6"></circle><circle cx="12" cy="12" r="2"></circle></svg>On the exam</p><p class="text-sm leading-relaxed text-foreground">For exfiltration questions, choose controls that hold regardless of what the model decides: no direct network interface, credentials injected outside the boundary, and a TLS-terminating proxy that can inspect traffic. Broad IAM on the agent, proxy environment variables on their own, and trusting the model's judgment all fail once the model is persuaded.</p></aside><aside aria-label="Exam trap" class="my-6"><p class="flex items-center gap-1.5 text-xs font-semibold uppercase tracking-wide text-amber-700 dark:text-amber-400"><svg xmlns="http://www.w3.org/2000/svg" width="24" height="24" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" class="lucide lucide-triangle-alert h-3.5 w-3.5 shrink-0" aria-hidden="true"><path d="m21.73 18-8-14a2 2 0 0 0-3.48 0l-8 14A2 2 0 0 0 4 21h16a2 2 0 0 0 1.73-3"></path><path d="M12 9v4"></path><path d="M12 17h.01"></path></svg>Exam trap</p><ol class="mt-3 space-y-3"><li id="exam-trap-3" class="scroll-mt-20"><details class="group rounded-lg border border-border bg-muted/20 p-4 open:bg-muted/40"><summary class="cursor-pointer list-none"><span class="flex items-start gap-2"><span class="min-w-0 text-sm font-medium leading-relaxed text-foreground [overflow-wrap:anywhere]">Setting HTTP_PROXY and HTTPS_PROXY is enough to force all agent traffic through a credential-injecting proxy.</span></span><span class="mt-1.5 block text-xs text-primary group-open:hidden ">Why is that wrong?</span></summary><p data-explanation="exam-trap-3" class="mt-2 text-sm leading-relaxed text-foreground">Proxy environment variables cannot enforce routing for tools that ignore them.
