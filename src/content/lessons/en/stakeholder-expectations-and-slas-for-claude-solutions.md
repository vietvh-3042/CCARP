They ask "will it be up?", and the honest answer depends on which tier the traffic runs on. Anthropic offers three tiers. Standard is the default for every API request. Priority Tier needs an existing capacity commitment. Batch is for asynchronous work that can wait. Promising availability you have not paid for is the most common way an SLA conversation goes wrong later.</p><p class="mt-4 leading-relaxed text-foreground"><strong class="font-semibold">Standard</strong> promises best effort and nothing more. Both come from your usage tier. Organisations are placed on a tier automatically from their usage history and move up over time, and new organisations may start in a lower Evaluation tier. These limits are enforced across the whole organisation. You can set lower limits of your own on individual workspaces, which is how one team's pilot is kept from using up another team's headroom.</p><p class="mt-4 leading-relaxed text-foreground">Rate limits on the Messages API are measured per model class as requests per minute (RPM), input tokens per minute (ITPM) and output tokens per minute (OTPM). They are enforced over shorter windows than their names suggest. A 60 RPM limit can behave like one request per second, so a burst can fail even when the minute's total is under the limit. Caching is the lever to explain to stakeholders: for most models only uncached input tokens count toward ITPM, so a high cache hit rate raises effective throughput without a tier change.
