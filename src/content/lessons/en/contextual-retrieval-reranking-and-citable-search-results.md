-->.</span>Retrieve broadly, fuse, rerank and pass the top-k</h2><p class="mt-4 leading-relaxed text-foreground">At query time, the pipeline turns a user's question into a short, well-ordered list of chunks. Ingestion has already built a BM25 index and a vector index over chunks that each carry a short generated context; for why both indexes are needed, see <a class="text-primary underline underline-offset-2 hover:no-underline" href="/en/lessons/retrieval-strategy-selection-full-context-embeddings-bm25-and-hybrid-search/">Semantic embeddings vs BM25, and hybrid search</a>. Each index returns its own ranking. BM25 ranks chunks by exact term matches, and the vector index ranks them by semantic similarity to the question, which is embedded with <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">input_type="query"</code>. Rank fusion then merges the two lists and removes duplicates, leaving one set of candidates.</p><p class="mt-4 leading-relaxed text-foreground">Retrieve broadly, then rerank narrowly. In a large knowledge base, the first retrieval can return hundreds of chunks of mixed relevance. A reranking model takes the query and the candidate list, scores each chunk for relevance, and you keep only the top-k. Anthropic's tests sent 150 candidates in and kept 20, using the Cohere reranker. Voyage offers <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">rerank-3</code> for the highest accuracy and <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">rerank-3-lite</code> when latency and cost matter more, both called with <code class="rounded bg-muted px-1 py-0.5 font-mono
