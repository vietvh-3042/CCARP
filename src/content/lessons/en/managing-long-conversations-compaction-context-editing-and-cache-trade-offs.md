It is the only server option where kept turns keep their thinking on models that preserve thinking. With threshold compaction, any turns you re-insert on Fable 5.1, Opus 5.5, Sonnet 5.5 or Haiku 5.5 must have their thinking removed. Either way, compaction is an extra sampling step, and it counts toward rate limits and billing.</p><p class="mt-4 leading-relaxed text-foreground">Client-side SDK compaction is the alternative. Server-side compaction is generally preferred over it. It runs in the TypeScript and Ruby SDKs through <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">tool_runner</code> with a <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">compaction_control</code> setting. After each response the SDK adds <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">input_tokens + cache_creation_input_tokens + cache_read_input_tokens + output_tokens</code>. Once that total passes <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">context_token_threshold</code> (100,000 by default), it injects a summary request and replaces the entire history with the summary. In the documented example, that takes the history from about 100k tokens to roughly 2–3k. A lower threshold means more frequent compactions and a smaller context. You can also set a cheaper <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">model</code> for writing summaries, or your own <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">summary_prompt</code>, as long as it wraps the summary in <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">&lt;summary&gt;&lt;/summary&gt;</code> tags.</p><p class="mt-4 leading-relaxed text-foreground">That sum can go wrong with server-side tools. After a web search, <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">cache_read_input_tokens</code> can include reads from several internal calls the tool made. A real context of 63,000 tokens then shows up as 334,400, and compaction fires far too early. Check the true length with the token counting endpoint, or avoid SDK compaction in workflows that use server tools heavily. Compaction suits long multi-file tasks and research runs with measurable progress and artifacts saved outside the conversation.
