How much are we using, and what does it cost? What exactly happened on this request? Where did this run spend its time? Claude Code and the Agent SDK answer each one with a different OpenTelemetry signal, and each signal has its own exporter. <strong class="font-semibold">Metrics</strong> are counters for tokens, cost, sessions, lines of code and tool decisions, so they suit totals and rates. <strong class="font-semibold">Log events</strong> are structured records for each prompt, API request, API error and tool result, so they answer "what happened". <strong class="font-semibold">Traces</strong> are spans for each interaction, model request, tool call and hook, so they show where the time went.</p><figure class="my-6"><figcaption class="mb-1.5 text-xs text-muted-foreground">Each signal, how it is enabled, and the backend types it suits</figcaption><div class="overflow-x-auto rounded-lg border border-border"><table class="min-w-full border-collapse text-sm"><thead><tr class="bg-muted/60"><th scope="col" class="px-3 py-2 text-left align-bottom font-semibold text-foreground">Signal</th><th scope="col" class="px-3 py-2 text-left align-bottom font-semibold text-foreground">Enable with</th><th scope="col" class="px-3 py-2 text-left align-bottom font-semibold text-foreground">Suited backends</th></tr></thead><tbody><tr class="border-t border-border align-top"><td class="px-3 py-2 text-foreground">Metrics</td><td class="px-3 py-2 text-foreground">OTEL_METRICS_EXPORTER (otlp, prometheus, console, none)</td><td class="px-3 py-2 text-foreground">Time series databases for rate calculations and aggregated metrics; columnar stores for complex queries and unique-user analysis</td></tr><tr class="border-t border-border align-top"><td class="px-3 py-2 text-foreground">Log events</td><td class="px-3 py-2 text-foreground">OTEL_LOGS_EXPORTER (otlp, console, none)</td><td class="px-3 py-2 text-foreground">Log aggregation systems for full-text search and log analysis; columnar stores for structured event analysis</td></tr><tr class="border-t border-border align-top"><td class="px-3 py-2 text-foreground">Traces (beta)</td><td class="px-3 py-2 text-foreground">OTEL_TRACES_EXPORTER plus CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1</td><td class="px-3 py-2 text-foreground">Distributed tracing systems for span visualization, request waterfalls and latency analysis</td></tr></tbody></table></div></figure><p class="mt-4 leading-relaxed text-foreground">A full-featured observability platform can hold all three. It earns its place when you need to correlate them, for example to jump from a cost spike in a metric to the events and spans behind it.</p><p class="mt-4 leading-relaxed text-foreground">Exporting takes several switches, and each one is a place for a CI rollout to go silently wrong. <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">CLAUDE_CODE_ENABLE_TELEMETRY=1</code> turns collection on, but it does not choose an exporter. The metrics and logs exporters are optional, and with neither set, nothing reaches the collector. If you pick <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">otlp</code>, you also need a protocol, because Claude Code has no default OTLP protocol. You need an endpoint too. <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">OTEL_EXPORTER_OTLP_HEADERS</code> carries whatever credential your collector expects. It is not an Anthropic key. <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1</code> matters only for traces, because metrics and log events do not need it. The console exporter is a debugging aid, not a prerequisite.</p><figure class="my-6"><figcaption class="mb-1.5 flex items-baseline justify-between gap-3"><span class="text-xs text-muted-foreground">A settings-file env block that sends metrics and log events to a gRPC OTLP collector</span><span class="shrink-0 rounded bg-muted px-1.5 py-0.5 font-mono text-[10px] uppercase tracking-wide text-muted-foreground">json</span></figcaption><pre class="overflow-x-auto rounded-lg border border-border bg-muted/50 p-4 text-[13px] leading-relaxed"><code class="font-mono text-foreground">{&#10;  <span class="text-primary">"env"</span>: {&#10;    <span class="text-primary">"CLAUDE_CODE_ENABLE_TELEMETRY"</span>: <span class="text-emerald-700 dark:text-emerald-400">"1"</span>,&#10;    <span class="text-primary">"OTEL_METRICS_EXPORTER"</span>: <span class="text-emerald-700 dark:text-emerald-400">"otlp"</span>,&#10;    <span class="text-primary">"OTEL_LOGS_EXPORTER"</span>: <span class="text-emerald-700 dark:text-emerald-400">"otlp"</span>,&#10;    <span class="text-primary">"OTEL_EXPORTER_OTLP_PROTOCOL"</span>: <span class="text-emerald-700 dark:text-emerald-400">"grpc"</span>,&#10;    <span class="text-primary">"OTEL_EXPORTER_OTLP_ENDPOINT"</span>: <span class="text-emerald-700 dark:text-emerald-400">"http://collector.example.com:4317"</span>,&#10;    <span class="text-primary">"OTEL_EXPORTER_OTLP_HEADERS"</span>: <span class="text-emerald-700 dark:text-emerald-400">"Authorization=Bearer example-token"</span>&#10;  }&#10;}</code></pre></figure><p class="mt-4 leading-relaxed text-foreground">The Agent SDK reads the same variables. In production, set them in the process environment: every <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">query()</code> call picks them up with no code change. Pass them per call through <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">ClaudeAgentOptions.env</code> only when different agents in one process need different telemetry. That option behaves differently in the two SDKs. In Python, <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">env</code> is merged on top of the inherited environment. In TypeScript, it replaces the inherited environment, so spread <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">process.env</code> into it or you lose <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">PATH</code> and your API key. The default metrics interval is 60 seconds and the default logs interval is 5 seconds.
