One prompt to an agent can turn into a dozen model requests, several tool calls, a wait for a human to approve a permission, and a subagent that makes its own requests. Each step depends on what the model chose in the step before, so running the same prompt twice can follow a different path. A log with one row per API call shows that request 7 returned <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">max_tokens</code>. It cannot show which turn request 7 belonged to, which agent sent it, or that the tool call before it waited four minutes for approval.</p><p class="mt-4 leading-relaxed text-foreground">Tracing puts those relationships back. Each turn becomes a <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">claude_code.interaction</code> span. Model calls and tool calls nest under it, and a tool span has separate children for the permission wait and for the execution itself. When the Agent tool starts a subagent, the subagent's own request and tool spans nest under the tool call that started it.</p><figure class="my-6"><figcaption class="mb-1.5 flex items-baseline justify-between gap-3"><span class="text-xs text-muted-foreground">The span tree for one Claude Code or Agent SDK turn</span><span class="shrink-0 rounded bg-muted px-1.5 py-0.5 font-mono text-[10px] uppercase tracking-wide text-muted-foreground">text</span></figcaption><pre class="overflow-x-auto rounded-lg border border-border bg-muted/50 p-4 text-[13px] leading-relaxed"><code class="font-mono text-foreground">claude_code.interaction&#10;├── claude_code.llm_request&#10;├── claude_code.hook                    (requires detailed beta tracing)&#10;└── claude_code.tool&#10; gate you open exposes more of every session on every machine (see <a class="text-primary underline underline-offset-2 hover:no-underline" The decision at scale is about exposure, not capability. One developer turning on prompt logging affects one person's sessions. The same gate in managed settings sends every engineer's prompts to a shared backend that many people can query.</p><p class="mt-4 leading-relaxed text-foreground">Some data reaches your backend even with every gate closed. Under OAuth, <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">user.email</code> is a telemetry attribute. It goes only to your collector, never to Anthropic, but your backend now stores it, so filter it there if your policy requires. The widest gate, <code class="rounded bg-muted px-1 py-0.5 font-mono text-[0.9em] text-foreground [overflow-wrap:anywhere]">OTEL_LOG_RAW_API_BODIES</code>, emits full request and response bodies, including the entire conversation history. Turning it on counts as consenting to everything the prompt, tool-detail and tool-content gates would reveal. It is rarely the right choice for a whole fleet.</p><p class="mt-4 leading-relaxed text-foreground">A narrower choice usually meets the real need.
